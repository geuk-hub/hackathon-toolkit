# 시작 프롬프트

경로와 남은 시간을 지정한 뒤 사용합니다. 목표는 계획에서 멈추지 않고 실제 구현을 시작하는 것입니다.

```text
이 작업은 시간이 제한된 실무형 코딩 과제다. 실제 과제 안내와 README, 기존 AGENTS.md를 우선해라.
과제 경로와 남은 구현 시간은 내가 지정한 값을 사용해라. 없으면 현재 경로를 확인하고 종료 시각만 짧게 물어라.

1. 현재 경로, 파일 구조, README, 실행/테스트 명령, 의존성 및 데이터 샘플을 먼저 확인해라. 비밀 파일은 출력하지 마라.
2. 필수 요구사항을 ID / 입력·출력 / 수락 기준 / 구현 위치 / 검증 방법으로 정리해라. 확정 사실과 가정을 구분해라.
3. 기능 구현을 막는 질문만 최대 3개 뽑아라. 업무 맥락은 내가 업무 담당자에게 확인할 질문으로 제안하고, 독립적인 작업은 계속해라.
4. 기존 스택을 우선해 가장 중요한 사용자 흐름 하나를 입력부터 출력까지 구현하고 실행해라. 전체 구조를 먼저 크게 만들지 마라.
5. 필수 기능을 순서대로 완성하고, 각 단계마다 실제 실행 결과로 확인해라. 정상/빈 입력/오류 및 중요한 경계값을 점검해라.
6. 주요 결정, 실행 명령, 확인된 결과, 미해결 사항만 작업 기록에 남겨라. 모든 토큰이나 내부 사고 과정을 기록할 필요는 없다.
7. 남은 시간의 마지막 15%는 새 기능 대신 검증·저장·제출 점검에 배정해라. 시간은 실행 환경에서 확인하거나 내 업데이트를 사용하고 추정으로 단정하지 마라.

먼저 발견한 환경, 필수 요구사항, 구현 순서를 짧게 보고한 다음 구현까지 진행해라.
시험 환경이 허용한 Codex와 도구만 사용해라. 외부 AI/개인 API 키/원격 전송/git push/Computer Use를 사용하지 마라.
UI 검증은 서버와 로직 검증 후 내가 직접 조작할 체크리스트를 제시해라. 자동 브라우저 조작을 하지 마라.
완료 보고에는 변경 파일, 실행한 검증과 결과, 미확인 항목, 제출 전 내 행동을 구분해라.
```
