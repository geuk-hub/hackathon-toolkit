# 검증

```text
구현 설명이 아니라 실제 파일과 실행 결과로 요구사항 충족을 검증해라.
요구사항 ID마다 구현 위치, 실행 명령/수동 절차, 기대 결과, 실제 결과, 통과/실패/미실행을 기록해라.
정상 사례 외에 빈 데이터, 경계값, 잘못된 입력, 중복, 오류 경로 중 해당 과제에 의미 있는 사례를 선정해라.
기존 테스트·타입 검사·빌드 중 적용되는 항목을 실행하고, 실패하면 원인을 수정한 뒤 영향받는 검사만 다시 실행해라.
핵심 API/처리 로직은 터미널에서 검증하되 UI를 직접 봤다고 주장하지 마라.
화면 확인은 내가 직접 수행할 '화면 → 조작 → 기대 변화' 체크리스트로 제시해라. Computer Use나 자동 브라우저 조작은 사용하지 마라.
README의 실행 절차를 안전한 별도 실행 환경에서 확인하고, 검증하려고 기존 데이터를 삭제하거나 전체 환경을 초기화하지 마라.
미실행과 실패를 통과와 분리하고, 시간상 검증하지 못한 사항은 명확히 표시해라.
```
