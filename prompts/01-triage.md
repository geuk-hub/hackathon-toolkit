# 요구사항·업무 맥락 정리

```text
과제 안내와 현재 저장소를 읽고 필수 요구사항의 누락을 찾아라.
각 요구사항에 ID를 붙이고 입력/출력, 예외, 완료 판정 기준, 구현 위치, 검증 방법을 표로 정리해라.
평가 기준이 제공됐다면 해당 항목과 연결하고, 제공되지 않았다면 배점이나 숨은 테스트를 만들어내지 마라.
모호한 사항은 확정/가정/질문으로 분리해라. 담당자에게는 '현재 해석 → 결과에 미치는 영향 → 구체적 질문'으로 최대 3개만 제안해라.
질문은 대상 사용자, 업무 용어, 데이터 기준, 실패 처리, 제출 형식 중 실제로 구현을 바꾸는 것에 집중해라.
필수/시간이 남을 때/이번 범위 제외를 나누고, 필수 요구사항을 임의로 버리지 마라.
답변이 없어도 되돌리기 쉬운 부분부터 진행해라. 데이터 손실·핵심 스키마·평가 정의처럼 되돌리기 어려운 가정은 먼저 확인해라.
```
