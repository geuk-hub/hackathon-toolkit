# 요구사항 분해

1. 실제 과제 경로와 남은 시간을 확인하라. README, 적용 지침, 파일 구조, 실행 명령, 데이터 샘플만 우선 읽어라.
2. 필수 요구사항을 ID, 입력/출력, 수락 기준, 구현 파일, 검증 방법에 연결하라. 제공되지 않은 배점은 추정하지 마라.
3. 사실·가정·질문을 분리하라. 구현을 바꾸는 질문을 최대 3개만 제시하고 독립적인 작업을 진행하라.
4. 핵심 사용자 흐름의 최소 작동 버전을 우선하라. 필수 기능과 선택 개선을 구분하고 기존 기술 스택을 유지하라.
5. 남은 시간의 마지막 15%를 검증·문서·제출 준비에 남겨라. 일정은 실제 시각과 사용자 정보에 맞춰 조정하라.
6. 짧은 계획 후 구현 요청이 있으면 실행으로 이어가라. 계획만 쓰고 끝내지 마라.

출력은 환경 요약, 요구사항 표, 핵심 질문, 첫 실행 단계로 제한하라. 비밀과 시험 자료를 외부로 전송하지 말고, 외부 AI·git push·Computer Use를 사용하지 마라.
