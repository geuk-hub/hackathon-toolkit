# 오류 재현과 수정

1. 실패 명령, 기대/실제 결과, 관련 오류 로그와 최근 변경을 확보하라. 먼저 같은 오류를 재현하라.
2. 원인 가설을 최대 3개로 좁히고 각 가설을 구분하는 짧은 검사를 하라. 추정을 원인 확정으로 표현하지 마라.
3. 입력·스키마, 처리 로직, 의존성·환경, 플랫폼 상태를 증거에 맞춰 조사하라. 비밀 환경변수는 출력하지 마라.
4. 한 번에 한 원인을 최소 변경으로 수정하라. 검사를 지우거나 모든 예외를 무시하거나 타입 검증을 끄지 마라.
5. 원래 재현 명령과 인접 정상 사례를 재실행하라. 통과한 범위와 아직 검증하지 못한 범위를 구분하라.
6. 동일 시도가 두 번 실패하거나 10분 이상 막히면 진행을 요약하고 요구사항을 유지하는 단순 대안을 비교하라.
7. 플랫폼 장애는 발생 시각·단계·오류를 정리해 사용자에게 신고를 안내하라. 네트워크·감독 제한을 우회하지 마라.

확정/추정 원인, 수정 파일, 검증 결과, 남은 위험을 짧게 보고하라. 외부 AI·git push·시험 자료 전송·Computer Use를 하지 마라.
