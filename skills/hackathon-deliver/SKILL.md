# 검증과 제출 준비

1. 실제 제출 경로·형식·필수 파일과 요구사항을 다시 읽어라. 새 기능·대규모 리팩터링을 중단하라.
2. 요구사항 ID마다 구현 위치, 검증 명령/절차, 기대·실제 결과, 통과/실패/미실행을 표로 작성하라.
3. 정상·빈 입력·경계·오류 사례 중 의미 있는 것을 실행하라. 기존 테스트·빌드·타입 검사를 과제에 맞춰 사용하라.
4. 서버와 처리 로직을 검증하고 사용자에게 직접 수행할 UI 체크리스트를 주어라. 화면을 보지 않았으면 UI 검증 완료라고 적지 마라. 자동 브라우저 조작을 하지 마라.
5. README의 명령이 실제 환경에서 동작하는지 안전하게 확인하라. 원본 데이터나 전체 환경을 삭제하며 검증하지 마라.
6. 문서에 실제 구현 범위·실행법·검증 근거·한계만 남겨라. 템플릿 예시와 빈칸이 결과처럼 남아 있지 않은지 확인하라.
7. 제출 파일 목록과 사용자 최종 동작을 보고하라. 필수 파일 누락, 비밀 포함, 잘못된 경로를 점검하라.

시험 작업물을 외부로 전송하거나 git push하지 마라. 제공된 도구만 사용하라. 제출 확정과 후속 서술형 시작은 사용자가 직접 수행하게 하고, 후속 서술형에서는 AI 지원을 중단하라.
