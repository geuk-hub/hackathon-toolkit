# 시간 배분과 막힘 대응

아래는 권장 작업 배분이며 공식 배점이나 고정 규칙이 아닙니다. 실제 남은 시간에 맞춰 줄이세요.

| 구간 | 180분 작업 예시 | 완료 조건 |
|---|---:|---|
| 요구사항·환경·입출력 확인 | 0–15분 | 수락 기준과 실행 경로 확인 |
| 핵심 사용자 흐름 연결 | 15–45분 | 실제 입력으로 최소 기능 실행 |
| 필수 기능 완성 | 45–120분 | 필수 요구사항 구현 |
| 오류·경계·연동 검증 | 120–155분 | 검증 근거와 결함 수정 |
| 재실행·문서·저장·제출 | 155–180분 | 재현 가능한 제출 상태 |

120분 연습이라면 10/20/50/25/15분으로 압축할 수 있습니다. 공식 시험은 과제 최대 180분과 별도 후속 서술형 절차가 있으므로 4시간 전체를 개발에 쓰지 않습니다. 늦게 시작하면 후속 절차까지 전체 종료 시각 안에 마쳐야 합니다.

## 모델에게 주는 정보

- 무엇을 달성할지: 사용자 행동과 기대 결과
- 어디서 작업할지: 실제 과제 경로
- 무엇을 지켜야 할지: 제출 계약, 기존 스택, 사용 가능한 데이터
- 얼마나 남았는지: 구현 시간과 제출 마감
- 어떻게 판단할지: 구체적인 입력과 기대 출력

## 막혔을 때

1. 실패 명령과 오류를 남기고 04-debug를 사용합니다.
2. 같은 실패를 반복하면 더 작은 입력과 한 기능으로 재현합니다.
3. 새 패키지/서비스 추가보다 기존 기능으로 해결 가능한지 확인합니다.
4. 필수 기능을 만족하는 단순 대안이 있으면 선택 이유를 기록합니다.
5. 플랫폼 오류는 Cofa Helper 또는 문제 신고로 구분해 문의합니다. 제한 우회로 해결하지 않습니다.

## 직접 확인할 UI

화면이 뜨는지 → 주요 입력 → 실행 → 결과 변화 → 오류/빈 상태 → 필요 시 새로고침 후 보존을 순서대로 확인합니다. URL/포트는 실제 환경에서 관찰한 값을 사용합니다. 서버 빌드 성공과 UI 검증 완료를 혼동하지 않습니다.
